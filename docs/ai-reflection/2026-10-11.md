## What to change next time

Lead with the action, the source of truth, and the limits, in one message.

A bare link, a file path, or "help me read" leaves the action open. These would have matched what you actually wanted:

- "Create a public Unreal 5.8 blank C++ repo named CameraSensor. Ask me before you commit."
- "Write a goal-only README from this file: `c:\Users\josen\Downloads\project-design-mt-camera.md`. The current design is Notion project P3, which drops SimHarness. Show me the text before you commit."
- "Here is the task: [Notion URL]. Evaluate the repo against it. Do not edit files."
- "Ignore the licence. Keep the current Git LFS rules. Leave the README for later. Write today's AI reflection and push it."

When a task card disagrees with a choice already made, say which one wins in that same message. The card says track only `.uasset` and `.umap`. You had already chosen a wider set. "I'm okay with the current LFS rules" settled it. Putting that next to the card would have avoided a possible rewrite.

Point at one current design. Two designs were in play today: the downloaded v1 file (SimHarness) and the approved Notion page (plugin `StallFreeCapture`, host `CaptureSandbox`, no SimHarness). Name the winner. A path alone makes the attached file the spec.

Check a dictated word when it names the action. "Roommate" was readable as README, and "down" was readable as done. A wrong repo name, file path, or "do" versus "evaluate" would have been followed literally.

Short check questions worked. "I saw two solution files, is that correct?" and "Did you create any git ignore yet?" got a direct answer. Keep using those after a setup step.
